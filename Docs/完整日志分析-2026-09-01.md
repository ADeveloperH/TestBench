## 四、明显的噪音 tag 候选

下面这批 tag 在本次日志里重复很多，但对常规功能测试、测试用例设计和业务排查帮助较小，比较适合作为“全局屏蔽候选”。

### 1. 强噪音，优先候选

- `voice_scence_discern`

    - `pAttribute->name :sample_rate`
    - `pAttribute->name :channels`
    - `add name:channels, value:2`

- `OplusFeedbackInfo`
  - 大量样例：
    - `mInputBufCnt = 0 fps ...`
    - `mInputBufCnt = 30 fps ...`
  - 主要是厂商视频/FPS 统计，对业务测试帮助很低

  - 大量样例：

  - 主要是系统音量与音频状态查询

- `ACodec`
  - 大量样例：
    - `Now uninitialized`

    - `Now Executing`

这些大多和音视频、系统媒体层有关，除非你后续要专门排查 H5 视频广告或播放器问题，否则都比较适合全局屏蔽。

## 五、SDK 日志中“有用但默认过多”的候选

这类日志和业务相关，但默认一直显示会让日志噪音很重。它们更适合：

- 默认隐藏
- 或做成“按 tag 全局屏蔽 / SDK 日志折叠”
- 而不是彻底删除

### 1. Beyla 埋点链路

相关 tag：

- `Android.BeylaManager.Up`
- `Android.BeylaDB`
- `Android.Stats`
- `Android.BeylaAnalytics`
- `Android.BeylaManager`
- `Android.BeylaCache`
- `Android.BeylaTracker`
- `Android.BeylaStats`

特点：

- 数量很多
- 会打印上传内容、缓存事件、统计事件
- 对普通功能测试意义不大
- 但对埋点、上传失败、事件丢失排查非常有用

建议：

- 默认隐藏
- 提供“显示埋点 SDK 日志”开关

### 2. 广告原生链路

相关 tag：

- `Android.Manager`
- `Android.ad_aggregation`
- `Android.H5AdSDK`

- 广告初始化、缓存、展示、H5、页面跳转都有日志

- 但对于一般玩法测试来说会显得吵

建议：

- 不建议直接全局屏蔽
- 更适合做“广告 SDK 日志组”的一键隐藏

### 3. 归因 / 渠道 / 云控 / 命令链路

特点：

- 调试网络、云控、渠道归因时有用
- 平时看功能流程时不一定需要

建议：

- 遇到相关问题时再打开

## 六、不建议全局屏蔽的 tag

这些 tag 即使量大或偶尔重复，也不建议做成默认屏蔽：

- `Unity`
  - 这是业务主日志入口
- `TD_JAVA`
  - 反作弊初始化和取黑盒日志，测试时通常有价值
- `Android.Manager`
  - 广告统一入口，常用于判断广告请求/展示流程是否真正发起
- `Android.ad_aggregation`
  - 广告聚合层日志，广告问题排查价值很高
- `NetWorkLog`
  - 虽然它在 `Unity` 内，不是外层 tag，但后续不要把它作为低价值文本噪音处理

## 七、对“全局屏蔽 tag”功能的建议

如果后续要做，我建议不要只做一个简单黑名单，而是做成三层能力：

### 1. 预置系统噪音屏蔽

内置一批默认候选，例如：

- `voice_scence_discern`
- `OplusFeedbackInfo`
- `AudioManager`
- `ACodec`
- `OplusACodec`
- `AudioTrack`
- `SurfaceUtils`
- `Parcel`
- `Settings`
- `VAppManager`

这是最安全的一层，默认开启也比较稳。

### 2. SDK 分组屏蔽

不要让用户一条一条选，建议按组开关：

- 隐藏埋点 SDK 日志
- 隐藏广告 SDK 日志
- 隐藏渠道/云控日志
- 隐藏系统媒体日志

这样维护成本和用户理解成本都更低。

### 3. 自定义全局屏蔽

最后再允许用户自己补充 tag 黑名单。

建议支持：

- 精确 tag
- 前缀匹配

因为当前日志里有很多 `Android.*` tag，本身就很适合前缀处理。
