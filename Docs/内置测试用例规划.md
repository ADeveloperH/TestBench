# 激励框架内置测试用例规划（长期工程）

> 目标：基于激励框架（IncentiveEngine + UnityPlugin）的日志体系，为 TestBench 设计内置测试用例，
> 覆盖「发现问题、排查问题」的常规回归场景。本文档持续更新，每个功能点都要评估是否有可加的规则。

## 一、日志机制说明

- 激励框架统一通过 `LogUtils.Info/Warning/Error/Exception` 输出日志，格式为 `[TAG]: message`
  （如 `[Withdraw]: 提现档位拉取失败: ...`），logcat 里 tag 均为 `Unity`。
- ⚠️ **LogUtils 的日志由 `ENABLE_LOG` 编译宏控制**（见 `Common/Log/LogUtils.cs`）。
  测试包必须定义 `ENABLE_LOG`，否则规则全部失效——落地前要先和游戏工程确认该宏开启。
- 网络响应另有 `NetWorkLog:Request/Response` 日志（Unity tag，含 `result_code` 字段），
  现有「网络响应异常」用例已基于它。

## 三、规则引擎现状与缺口

当前规则引擎是「命中即触发」（error/warn/pass），存在两个已知缺口，影响用例设计：

1. **缺失判定**：无法表达「启动后应出现『所有SDK初始化完成』，没出现 = 失败」（哨兵日志类用例）。
2. **出现 N 次阈值**：无法表达「累计出现 3 次才算异常」。

这两个缺口建议作为规则引擎增强排期；本文档中依赖它们的用例先标注 `[需缺失判定]` / `[需N次阈值]`。

## 四、UnityPlugin 插件部分

### 4.1 Analytics 埋点插件（analyticsplugin）

功能：数据埋点/事件统计，JNI 桥接 Android 原生上报，非 Android 用 `DefaultAnalytics` 兜底。
日志封装：自定义 `Logger`（受 `LoggerEnable` 开关控制）。

| 功能点 | 规则（message contains） | 效果 | 说明 |
|---|---|---|---|
| Android 初始化方法已移除 | `Android 初始化方法已移除` | error | 唯一 error，固定文案；要求改到自定义 Activity 初始化 |
| 兜底实现调用 | `DefaultAnalytics.` | warn | 编辑器/iOS 走兜底（Init/TrackEvent/TrackPageIn/Out 等 7 条） |

### 4.2 Config 云控插件（configplugin）

功能：云控配置读写（bool/int/long/string、A/B 实验码、KV 配置、监听与强制拉取），非 Android 兜底。
注意：`DefaultCloudConfig.*` 是「走了兜底实现」的标记，真机出现 = 桥接未生效。

| 功能点 | 规则（message contains） | 效果 | 说明 |
|---|---|---|---|
| 配置类型转换失败 | `转换失败：` | error | 唯一 error，HashMap 转 C# Dictionary 失败 |
| 重复初始化 | `ConfigPlugin CloudConfigManager has already init` | warn | 重复 Init 调用 |
| 走兜底实现 | `DefaultCloudConfig ` | warn | 真机出现 = Android 桥接没生效，重点排查 |
| 正常初始化 | `ConfigPlugin CloudConfigManager init:appID` | pass | 真机初始化成功 |

## 五、落地计划建议

1. **前置确认**：✅ 已确认——只有测试包开启 `ENABLE_LOG`，测试使用 TEST 包（`#if TEST`）；
2. **第一批**：✅ 已落地 13 个用例 / 28 条规则（id 前缀 `ie_`，见 `engine.ts` IE_CASES）；
   ⚠️ 待修正：`ServerError - Type:` 与 `InvalidData - Type:`（NetworkDelegate）当前**无调用点**（预留接口），相关规则暂缓，等框架接线后再加；`NetWorkLog:Response` 为游戏侧网络封装日志，与框架无关；
3. **第二批**：插件部分（4.1~4.6）的 error 规则 + 引擎层 F~J 的 error/warn 规则（Push 8 条 exception、Config 转换失败、AD 预加载校验等）；
4. **引擎增强**：✅ 已完成——缺失判定（锚点 + 观察窗口）、出现 N 次阈值（minCount）、规则变更自动重置状态；哨兵类 pass 用例可陆续补充（如 `所有SDK初始化完成`、`LoadAd 加载成功`，已加 `ie_sdk_init` 示例）；
5. **持续维护**：本文档作为长期资产，框架每更新一个版本，回头核对其新增日志点、补充新规则。
