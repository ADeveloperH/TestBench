# iOS 阶段 2 任务清单

更新时间：2026-11-09

IOS2-230 实施约定（2026-11-05）：复用现有 TanStack 虚拟滚动依赖；展示窗口仍为 5000 条。搜索只影响展示，保留 Apple 原始级别与 Unity 推断级别分别筛选；选中记录展示完整 raw，不修复乱码。支持跟随最新与暂停跟随，列表溢出提示不得暗示原始落盘丢失。代码完成后保留运行时验收状态。

## 一、目标与边界

阶段 2 的目标是在不改变现有 Android 设备、Logcat、测试用例和正式日志页行为的前提下，完成 iOS 设备发现与日志采集的 TestBench 端到端验证：

```text
内置 go-ios sidecar
→ Tauri/Rust 会话管理
→ 有界队列与批量日志事件
→ 开发模式或内部验收包可见的 iOS Probe 页面
→ macOS / Windows 安装包验证
```

本阶段保持 iOS 能力隔离，不提前实施 Android/iOS 通用设备模型、正式日志页接入、Wi-Fi 连接、安装卸载、投屏录屏或测试用例引擎接入。正式架构改造属于阶段 3。

### 1.1 代码审核后的实施约束

2026-11-04 对合并后代码再次审核，阶段 2 增加以下硬性约束：

1. Probe 页面不能只依赖 `IS_DEBUG`。`pnpm tauri build` 的前端生产包中 `IS_DEBUG=false`，因此增加独立的内部验收构建开关 `VITE_ENABLE_IOS_PROBE=true`；普通正式包默认关闭。
2. 设备“在线”“已信任”“锁定”不是同一个互斥状态。锁屏设备仍可能保持 syslog 能力，阶段 2 分别表达连接、信任、锁定信息和能力，不把锁屏直接等同于不可用。
3. `doctor` 返回工具、Apple 系统服务、设备通信和设备列表的分项诊断，不能用单个 `deviceAccess=true/false` 概括。
4. Rust 批处理不等于背压。读取线程与 Tauri 事件发送之间必须使用有界队列，并分别统计接收、发送、后端丢弃和前端丢弃数量。
5. 原始日志必须先落盘再允许展示链路丢弃；Android 与 iOS 使用独立会话状态和平台目录。
6. 开发环境和正式安装包采用不同的工具查找策略；正式包只能启动资源目录中的固定版本工具，缺失时报告安装损坏。
7. 常规停止按当前会话持有的子进程句柄回收。Windows 的 `taskkill ios.exe` 只能作为更新/退出异常兜底，不能作为日常停止方式。

### 1.2 阶段 2 与最终 UI 的关系

阶段 2 的 `IosProbePage` 是临时工程验证页，用于单独验收 go-ios、Tauri 会话、事件吞吐和安装包资源路径，不是最终用户长期使用的一套 iOS 专属界面。

阶段 3 验收通过后，iOS 接入现有正式日志工作区，复用设备选择、采集控制、搜索筛选、虚拟列表、详情、导出和测试用例侧栏。平台差异通过设备能力和局部控件适配表达，例如 Android 的 Logcat Buffer、iOS 的信任状态和推断级别；不复制两套完整日志 UI。临时 Probe 页在统一日志页达到等价验收后删除或仅保留为内部诊断工具。

### 1.3 共享 Rust crate 边界

```text
tools/ios-core
├── device：设备数据结构、枚举与状态归一化
├── error：稳定错误类型和 go-ios 错误分类
├── syslog：原始 envelope/syslog 解析与 Unity 有限语义推断
└── tool：工具路径封装、执行与固定版本校验

tools/ios-probe
├── CLI 参数与 JSON 输出
├── CLI 开发环境工具查找
└── Ctrl+C、stdout/stderr 读取与子进程回收

src-tauri（阶段 2 后续任务）
├── 安装包 resource_dir 路径策略
├── AppHandle/Event 与有界队列
└── 会话、落盘和应用生命周期
```

`ios-core` 不依赖 Tauri，不注册全局 Ctrl+C，不持有应用会话，也不决定正式包是否允许回退 PATH。CLI 和 Tauri 共同依赖同一解析、设备和错误语义，环境与生命周期由各自适配层负责。

## 二、任务编号与状态约定

- 任务号格式：`IOS2-xxx`；`2` 表示阶段 2，后三位按实施顺序递增。
- 状态仅使用：`待开始`、`进行中`、`已阻塞`、`待验收`、`已完成`。
- 一个任务只有在代码、测试、文档和对应验收项均满足后才能标记为 `已完成`。
- 提交信息、问题描述和验证记录优先引用任务号，例如：`IOS2-120：实现 iOS 日志会话停止与回收`。
- 新发现但不属于当前任务范围的工作，新增任务号记录，不悄悄扩大原任务。

## 六、统一验证要求

每个相关实现任务至少执行项目约定的检查：

```bash
node scripts/validate-config.mjs
pnpm exec tsc --noEmit
pnpm build
git diff --check
```

Rust 变更还需执行对应 crate 的 `cargo test` 和 `cargo check`。如果触及测试用例配置，额外执行：

```bash
node --test scripts/tests/test-case-config.test.mjs
```

验收记录必须区分：

1. 纯逻辑/解析器自动化测试；
2. 浏览器或 WebView 界面验证；
3. 真实 Tauri 运行时与真机验证；
4. 安装包资源和目标平台验证。
