## 阶段 1 入口

独立 CLI 位于 `tools/ios-probe`，当前提供：

- `doctor`：检查平台、工具版本和设备访问能力
- `list`：输出经过字段裁剪和状态归一化的设备列表
- `logs`：解析原始 syslog，支持按进程过滤和 Ctrl+C 回收

共享 Rust 库位于 `tools/ios-core`，统一维护设备模型、错误分类、go-ios 固定版本检查和 syslog 解析。CLI 与 Tauri 后端均依赖该库。

可控日志测试包位于 `<unity-fixture-dir>`。当前已确认 Bundle ID `com.testbench.ioslogfixture` 能安装到真机，实际进程名为 `TestBenchiOSLogFixture`。下一步使用测试界面逐项建立日志能力矩阵。

具体命令参见 `tools/ios-probe/README.md`。

## 维护约定

- 高频框架日志屏蔽（2026-11-16）：正式 iOS 日志页默认隐藏 WebKit JavaScript 活动开始/结束、AudioToolbox completion 与 UIKitCore 后台任务常规状态三类精确 notice 消息；设置→日志屏蔽可分别关闭，工具栏可临时显示。原始落盘、完整会话导出及 Probe 不屏蔽；网络和后台任务异常日志保留。自测证据与边界见 [UI 对齐计划](iOS正式日志面板UI对齐计划.md)。

1. 调研结论、工具版本和兼容性结论应注明验证日期与测试环境。
2. MVP 阶段采集的原始输出样本不要包含账号、设备所有者或业务敏感信息。
3. 工具选型在真机验证通过前均视为候选方案，不提前绑定正式业务接口。
4. 正式接入时保持 Android 功能不回归，并通过平台能力控制不同设备可用的功能。
5. Windows 上区分“TestBench 内置工具”和“Apple 系统 USB 驱动”两个依赖层，不把驱动缺失误报为普通设备离线。
