### 源码现状与约束

- `engine.ts` 条件只支持 message/tag/level，直接读取 Android LogEntry；`useTestCases` 按数字 id 增量消费、包名作用域与 PID 过滤，保留 minCount、absence、requirePass 和五种运行结果。Sidebar 的输入、命中证据及定位也绑定 LogEntry/数字 id。
- Android 测试 Tab 从开始边界之后、应用 pidHistory 的原始缓冲构建，绕过普通搜索与 Tag 屏蔽；iOS Tab 当前没有测试种类、应用绑定或测试起点，正式分支不渲染测试侧栏。不能只给 iOS 加一个侧栏就视为对接完成。
- 本地 `config/remote-config.json` 的47个内置用例（不是承诺运行时远程清单固定为47）：31个含 Unity Tag 条件且不检查级别，14个涉及其他 Tag 或级别，2个仅正文；后两者分别是 Beyla 数据与 Android 云控缓存检查，仍需业务审核。31个只是候选，不能直接认定 iOS 通用。

### 建议接入契约

1. 复用规则树、计数/缺失状态机、用例管理、测试 Tab 外观和侧栏；提取监测专用输入/证据接口，Android 走原适配，iOS 走独立适配。不构造假的 Android Tag/TID 或把 notice 映射成 I；元数据、来源引用和原文保持可追溯。
2. 用例显式声明适用平台；旧定义缺少平台时按 Android 处理，避免现有 global 用例自动跑到 iOS。iOS 新定义使用独立唯一 ID；内置身份仍由当前 builtinRegistry 决定，远程 testCases 整段替换与启停覆盖语义不变。
3. 应用作用域必须带平台：Android 包名与 iOS Bundle ID 独立，不从名字/包名猜映射。首批 iOS 测试仅绑定正式页当前已确认的单应用精确采集会话；全部应用、Probe 前缀或无法确认映射时不能声称应用范围已满足。另一测试 Tab 不得静默改变共享采集应用；换应用需要停止并开启新会话。可执行名匹配仍不等同于完整 PID/扩展归属。
4. message 对 iOS 采用已验证的 MacRoman 还原正文（不能还原时使用原正文），一次记录只计一次；证据保留 raw、原 message 与还原标识。规则不对 raw/还原两份内容分别计数，也不把它们拼接后执行否定条件。
5. iOS 可提供 module/process、Apple 原始级别与 Unity 推断级别；Android Tag/字母级别原义保持。缺失字段不能用空字符串代替后执行 not_contains/not_equals，否则会产生假命中；未知 Unity 级别不视为 Info，也不能满足“不是 error”。平台选定后先进行适用性校验，不能删除不支持的条件或拆掉 AND/OR 子树以求匹配。
6. 不适用/未适配显示独立的适用性原因，不硬塞进 fail/pass，不改原有 CaseStatus 计算。旧 Android Tag 专属用例在 iOS 不执行；要复用 Unity 业务规则，应新增经审核的 iOS 版本，以真实 module 和正文特征替代 Tag 限定，而不是伪造 Unity Tag。
7. 测试输入来自捕获原始记录序列，位于普通视图搜索、暂停快照、清空和三组降噪之前；不能以 selectIosRecords 的可见结果驱动引擎。运行身份至少包含 platform/device/captureSession/testTab/testRound，sequence 仅在当前会话内比较，命中定位使用来源记录键。
8. 明确“清空展示”和“重新开始测试”不同；新测试从当前 sequence 之后开始，不默认回放历史。切 Tab/进入 Probe 不停止测试消费；需把监测生命周期从侧栏挂载中解耦，否则后台 Tab 会漏评估。停止/断线结束本轮采集关联的监测，保留证据并提示中断，不让失联后的时钟继续制造缺失结论；重新采集建立新轮次。连续有效采集内的原锚点、withinSec、minCount、requirePass 语义保持。
9. 事件丢弃、隐私隐藏、截断/无法还原等采集限制必须提示；未观察到错误不等于无崩溃，不能承诺仅靠 Syslog 判断完整崩溃。已缓存的命中证据淘汰后仍可在详情查看，定位到列表时说明记录已移出窗口，不跳到其他会话或同序号记录。
10. 配置兼容纳入首批设计：当前 version 2 配置继续可读，旧规则默认 Android；新平台字段/作用域/条件须同步校验、编辑器、运行指纹与导入去重。不能把新增字段发给不认识它的旧客户端后任其退化为 level 匹配。新增定义的能力标识/版本门禁与旧客户端安全导出策略在实施前确定；本轮不修改远程发布配置。

## 源码审核结论

| 现有入口 | 当前耦合与接入要求 |
|---|---|
| `src/core/types.ts` | Device 以 Android serial 为身份，LogEntry 强制 Android 级别、Tag、TID；需要增量引入平台描述与日志来源，不能直接强转 IosLogRecord |
| `src/features/logcat/useLogcat.ts` | 集中持有设备轮询、ADB 自动重连、buffer、解析、事件、展示缓冲和导出；设备或 buffer 切换可能重启采集。保留 Android 路径，增加工作区协调层路由平台 |
| `src/features/logcat/useLogTabs.ts` | Tab 保存筛选、应用包名、PID 历史和日志 ID 边界；运行态启动后清零。需要平台/来源绑定和旧缓存迁移，防止 iOS 记录被 Android Tab 消费 |
| `src/App.tsx` | 同时管理应用运行状态、PID 解析、过滤投影、测试 Tab 和工具调用；App 只组装新协调层，不继续内联平台分支 |
| `src/core/logcat.ts`、`src/features/logcat/LogList.tsx` | 筛选与列表使用 Android LogEntry；保留 Android 堆栈/分块处理，iOS 使用自己的适配器，复用列表外壳与虚拟化 |
| `src/features/testcases/useTestCases.ts`、`engine.ts` | 按 scopePkg、pidFilter、sessionKey、递增日志 ID 消费记录；平台接入必须明确作用域和级别语义，不能把进程名前缀当包名 |
| `src/features/ios/useIosProbe.ts`、`src-tauri/src/ios` | 已有独立事件、状态、原文及落盘；Probe Hook 绑定页面生命周期且批事件无会话身份，正式接入前需建立单一订阅者和会话代号 |

## 设备与 Provider 契约
