# 手机自动化素材录制

更新：2026-11-16。第一版目标为 Android 单设备运行“通用录屏素材 Mock 数据”。本文是 TestBench 的实现约定；Unity 共用契约维护在自动化插件的 Docs/TestBench协议.md。

## 界面与会话

- 保留现有工具栏、Tab 栏、普通日志及测试用例界面。在“＋”菜单中新增自动化类型，自动化 Tab 仅展示自动化配置、步骤和结果。
- 日志和用例通过切换 Tab 查看。切页不停止执行，不重建日志采集；日志暂停/清空不能改变自动化任务。运行时禁止关闭所属 Tab 或切换受占用设备，先显式停止并收尾；重启、清数据、安装、卸载、交互投屏与手工录屏由后端拒绝，避免切页绕过保护。
- 自动化 Tab 绑定设备、应用；后端持有运行状态，React 组件卸载不能停止任务。重启 TestBench 不自动重放副作用。启动任务时保留日志起点，关联的日志/用例 Tab 复用本轮起点及跨重启 PID；切换 Tab 不重新开始测试。
- 启动准备阶段立即锁定配置和所属Tab，禁止重复启动。日志采集启动失败则不派发自动化；新采集会话的日志ID从零开始，关联起点必须同步重置，不能沿用上次采集的ID。
- 无支持自动化的 APK 时显示连接前置条件；不伪造可运行场景、进度或成功结果。

## 自动化界面与执行方案（2026-11-16）

- 页面统一称“自动化测试”，配置区称“执行配置”，主操作称“运行/停止”。素材专有的片段和录屏参数保留在当前场景表单。
- 创建自动化Tab时绑定当前设备及所选应用；创建前必须有设备。绑定在Tab存续期间固定，页面仅展示只读设备/应用及连接状态、连接/重新连接/断开操作。顶部设备选择不会重新绑定已有Tab。
- 页面移除“查看日志/测试用例”的重复按钮，关联日志/用例Tab及运行期间锁定、切页不中断逻辑保留。
- 场景列表来自测试包catalog，按真实场景ID切换，不在界面固定material_capture_mock。当前参数编辑器仍遵循共用Version 4片段契约，新增不同参数模型的测试类型需要扩展契约和表单。
- “游戏默认”是来自当前测试包的只读方案来源；修改参数只产生草稿，保存时创建具名方案。自定义方案支持保存、另存、重命名、删除及撤销最近删除。切换场景/方案或刷新列表会提示放弃未保存改动；运行可采用未保存草稿，冻结快照仍写入本次输出。
- 具名方案按应用包名＋场景ID保存为TestBench应用数据目录automation/plans/<包名>/<场景ID>/plans.json，同应用可跨手机复用，不反写APK和游戏项目。JSON包含schema版本、修订号、方案名称/参数及可撤销删除项。写入原子替换，修订号冲突拒绝覆盖；损坏数据明确提示，不用空列表覆盖原文件。
- 原automation-task-v1:<设备>:<包名>缓存首次读取时幂等迁移为具名“原设备配置”；原缓存保留。同一应用的不同设备旧配置分别保留，迁移不修改关卡/提现/环境/音频参数。Tab草稿和选中项仅在本机独立缓存，不等同于已保存方案。
- 方案管理属于TestBench本地命令，不改变手机桥协议。运行/连接准备期间锁定方案与参数写入；导入导出继续兼容Editor的Automation.json格式。

## 共用编排

- Editor 和手机共用参数模型、片段排序、环境校验、业务模板、流程展开及 FlowEngine。桌面不复制业务编排规则。
- Editor 保存 ProjectSettings/Automation.json；测试构建导出场景目录与默认配置；TestBench 只保存本机覆盖及本次冻结快照，支持配置导入导出。
- 模板和默认值由测试包提供。首次连接读取实际国家及配置，不在 TestBench 写死国家或游戏适配。2026-11-15起，激励业务两个内置素材场景的初始默认片段为成功55不提现、成功66不提现、成功88附加提现、失败99，声音默认开启；具体仍以测试包目录为准。已保存的本机覆盖不会被框架默认值更新自动替换，可用“恢复游戏默认”读取当前测试包提供的配置。
- 配置修改后由手机共用编译器校验/展开；每国冻结完整文档。运行期间锁定配置。

## 手机与宿主

- adb forward + TCP JSONL，手机只监听 loopback；所有命令显式绑定设备/包名，协议协商后才能运行。
- 使用自动化启动标记进入配置等待门，在登录前注入国家、Mock 及广告策略。普通启动不等待配置。切国家由桌面重启，不能运行中换环境。
- Unity 主线程执行流程；后台线程只处理有界网络消息。录屏请求及确认非阻塞，不能在主线程等待电脑进程。
- TestBench 管理 scrcpy 手机录屏、截图、输出目录和报告；录屏宿主确认就绪后流程才可继续。进程存活不代表视频已就绪。
- 请求/回复关联 requestId、runId、country、clipId；心跳丢失时有界取消。断线后查询状态，不盲目重发领奖/提现。
- 正式包禁 ENABLE_AUTOMATION；自动化代码、启动桥、目录资源仅专用自动化构建包含（ENABLE_AUTOMATION，激励业务同时启用 TEST）；Development 非必需。
- 启动/prepare失败时，不向尚未建立的runId发送stop或拉取业务诊断，保存原始错误和失败阶段，停止本次启动的应用。后续连接断开只能改变连接状态，不能覆盖已归档的任务终态和首个业务错误。

## 输出与结果

AutomationOutput/<本地时间到秒>/video_<游戏>/<国家>/ 仅存已完成并校验的视频；config、reports、diagnostics 同级。成功片段独立交付，后续失败不撤销。规则不可达保留诊断，不能当作成功素材。请求/响应及错误码纳入诊断，敏感字段脱敏。手机在登录前开始归档 NetWorkLog:Request/Response，宿主分块增量拉取，断线时保留已收到部分。连接/准备失败也必须写入本次报告；取消和规则不可达分别标识，不将其当作完成。界面仅展示最近步骤，完整报告保存在输出目录。

## 操作入口与文件

“顶部选择设备 → ＋ → 自动化 → 选择应用 → 创建Tab”，设备和应用绑定后固定。点击连接测试包，读取真实目录后选择场景/执行方案、调整参数并运行；日志和用例通过各自Tab查看。会话选中设备与全局日志采集设备同步，运行期间保护占用。常规资料留空由业务按地区生成，可选资料默认折叠。导出使用系统保存对话框，默认文件Automation.json。

```text
AutomationOutput/2026-11-14_23-00-00/
  video_<游戏工程>/<国家>/*.mp4
  config/task.json              # 本次原始参数及目录快照
  config/<国家>.json            # 手机校验后的冻结文档
  reports/materials.json        # 累积国家/片段结果，完成/部分完成/取消
  reports/<国家>.json           # 手机终态预览
  reports/<国家>-full.json      # 手机完整步骤与诊断
  reports/<国家>-error.json     # 启动、准备、协议、执行或录屏错误
  diagnostics/<国家>/          # network.jsonl、截图、中断/不可达视频及录屏日志
```

一个片段完成后立即移动到交付目录；不等待整国或整批成功。桌面默认输出根为Documents/TestBench/AutomationOutput，可在录屏与输出中更改。国家失败继续后续国家；当前玩法规则不可达仅跳过当前片段、保留证据。手工录屏/故障报告活动期间不能启动自动化；运行期间拒绝会破坏任务的设备操作。手机保持前台、解锁，退出已有交互投屏；电脑可继续工作。专用Unity会话保持屏幕唤醒并在释放时恢复，scrcpy禁止控制，不使用与该参数互斥的stay-awake。
