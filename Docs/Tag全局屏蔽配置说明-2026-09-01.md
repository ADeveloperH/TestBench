# Tag 全局屏蔽配置说明（2026-09-01）

## 一、功能边界

- 只影响普通日志 Tab 的显示结果。
- 测试用例 Tab 的日志显示和规则检测始终使用完整原始日志。
- 普通日志页的“导出”跟随当前可见结果。
- “导出调试日志”和底层原始日志缓冲不受屏蔽影响。
- 普通日志页显示当前视图“已隐藏 N 条”，可临时显示被屏蔽日志。
- 普通日志详情支持从当前 Logcat Tag 快捷添加本地屏蔽规则。

## 二、远程配置

远程内置规则位于 `config/remote-config.json` 的 `tagBlockRules` section：

```json
{
  "id": "noise_audio_manager",
  "value": "AudioManager",
  "description": "系统音量查询噪音",
  "match": "exact",
  "group": "系统与媒体",
  "enabledByDefault": true
}
```

字段说明：

- `id`：稳定唯一标识，远程更新时用于保留用户顺序和启用状态。
- `value`：外层 Logcat Tag，不匹配 Unity message 内的业务前缀。
- `description`：维护说明和界面提示。
- `match`：`exact` 为精确匹配，`prefix` 为前缀匹配。
- `group`：界面分组名称，可按组启用或关闭。
- `enabledByDefault`：用户从未调整该规则时使用的默认状态。

远程配置会拒绝重复 `id`，也会拒绝相同 `match + value` 的重复规则。

## 三、本地配置

本地偏好只保存用户状态，不复制远程规则定义：

- `tagBlockingEnabled`：普通日志页总开关。
- `customTagBlockRules`：用户本地自定义规则。
- `tagBlockEnabledOverrides`：用户明确调整过的规则开关。

合并规则：

- 远程 section 整段覆盖代码兜底规则。
- 内置与本地规则合并后统一按 Tag 名称排序，不提供手动排序。
- 远程可更新 Tag、描述、匹配方式和分组。
- 用户调整过的启用状态不会被远程 `enabledByDefault` 覆盖。
- 本地自定义规则不会被远程覆盖。
- 远程删除的内置规则会从生效列表移除。

## 四、代码兜底

代码兜底规则位于 `src/core/builtins.ts` 的 `BUILTIN_TAG_BLOCK_RULES`。

修改正式默认规则时，应同步修改：

- `src/core/builtins.ts`
- `config/remote-config.json`

然后运行：

```bash
node scripts/validate-config.mjs
pnpm build
```

## 五、当前默认名单

第一版内置 20 条低风险系统/媒体噪音规则，全部使用精确匹配并默认启用。业务关键 Tag（例如 `Unity`、`TD_JAVA`、`Android.Manager`、`Android.ad_aggregation`）不在默认屏蔽名单中。

埋点、广告、渠道和云控 SDK 规则后续可以作为新分组远程追加，建议默认关闭，由用户按排查场景启用。
