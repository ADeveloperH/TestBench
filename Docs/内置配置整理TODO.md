## 配置规范

- 明确内置配置的统一约束：代码兜底、远程内置、本地用户数据三层各自职责。
- 明确哪些字段允许进入内置配置，哪些字段只能作为运行时状态存在。
- 补一份命名规范：应用、Tag 常用、过滤器、测试用例的 `id/name/value/group` 约定。

## 过滤器

- 清理内置过滤器中的瞬时字段，重点确认 `pid` 不进入内置配置。
- 统一过滤器的“去重指纹”规则，避免因 `pid` 等瞬时值导致重复导入。
- 明确过滤器哪些字段参与保存、导入导出、远程配置和内置判定。
- 补过滤器配置校验，拦截非法字段和不合规内置项。

## Tag / 常用项

- 补 Tag / 搜索常用的去重、排序和校验规则。
- 评估并设计“按 tag 全局屏蔽”能力，先从系统/媒体噪音 tag 的默认屏蔽名单开始。

## 测试用例

- 明确测试用例分组规范，统一 `group` 命名。
- 明确测试用例 `id` 命名规范，区分通用用例和业务/插件用例。
- 补测试用例深校验：`rules / expr / minCount / absence / scope`。
- 评估测试规则读取系统 PID 的能力，让 ANR 等系统进程规则可执行。
- 评估带时间窗口的次数阈值，支持“最近 N 秒连续失败 M 次”。

## 远程配置与发布

- 明确 `remote-config.json` 每个 section 的字段约束和维护规则。
- 强化 `scripts/validate-config.mjs`，让非法配置在提交前就失败。
- 评估是否把大 JSON 拆成分段来源，再生成总配置，降低维护成本。
- 统一配置更新时间、变更说明和发布检查步骤。
