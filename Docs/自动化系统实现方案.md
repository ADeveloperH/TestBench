## 2. 当前目标与完成边界

编排由 AI 维护，使用者配置任务参数并启动确定性执行。AI 负责理解游戏、编写和维护图及能力代码；运行过程中不依赖模型临时判断下一步。

当前实现位于 **Unity Editor**：正常入口启动游戏，依次准备关卡、操作真实玩法、处理框架业务、录制多个独立片段，输出视频和可排查的报告。可视化用于只读查看节点、子流程及运行状态，日常不通过画布人工编程。

| 能力 | 当前状态 | 使用边界 |
| --- | --- | --- |
| Editor 编排、子流程、分支、有限重复、等待和断言 | 已实现 | JSON 场景 schema 2；实际走通允许分支不代表全分支覆盖 |
| 成功/失败视频，成功可附加提现 | 已实现（本轮待用户实测） | 提现与所属成功连续录制为同一个视频，余额不足只跳过提现 |
| 多国家、按关卡排序、真实接口准备 | 已实现 | 当前支持 ID/BR/MY/PH/TH/VN 中游戏实际启用的国家 |
| 音频、录屏参数、运行快照、网络诊断 | 已实现 | 采集 Unity 游戏混音；实际码率随画面变化 |
| 新游戏接入机制 | 已实现接口和注册 | 目前实际接入样本只有 Fortuna；每种新玩法仍需适配和实录验收 |
| 桌面后台持续录制与完整输入隔离 | 部分基础支持，完整方案待做 | 当前仍有失焦降帧、人工输入干扰及逐步聚焦问题 |

### 成功片段附加提现：当前约定

- 素材计划升级为Version 3；只添加成功/失败片段。每个成功片段独立设置`Withdrawal.Enabled`及各国渠道/账号覆盖，默认不附加提现。
- 勾选后保持同一条录屏：关卡加载→通关→宝箱奖励→金币动画结束→核对实际余额和门槛→提现入口/输入/勾选/提交/成功页→停录。不生成单独提现视频，不在两者之间做引导往返。
- 首次核对余额不足时不进入提现页；入页/渠道刷新后若余额不足则停止该次提现，不补币、不跳关凑门槛、不将业务拒绝视作可跳过；成功部分照常停录。每次成功后重新核对，支持多个成功片段各自附加。
- 报告、执行日志及片段元数据记录国家、片段ID、余额、门槛、结果和原因码`insufficient_balance`。未勾选与余额不足跳过要区分。
- Version 2旧独立提现迁移到按执行顺序最后一个启用成功片段，保留渠道、手工资料和生成模式；没有可匹配成功或多个旧提现时明确报错，由AI处理，避免静默丢数据。历史产物/快照不改。
- 实际Editor操作由用户验收，本轮不运行Unity Editor测试；编译和非Editor逻辑检查单独记录。

## 3. 框架、游戏和 TestBench 的职责

| 层 | 应维护的内容 | 不应混入的内容 |
| --- | --- | --- |
| 框架编排核心 | 图模型/校验/执行、任务组合、注册发现、窗口、计时/输入会话、录屏、快照和输出 | 水果/麻将等具体玩法、具体游戏对象名 |
| 框架业务能力 | `framework.*`：环境、升级/领奖、余额、广告成功回调、提现、框架弹窗、网络诊断 | 从游戏适配器复制一套通用框架逻辑 |
| 游戏适配 | `game.*`：正常加载关卡、引导、真实操作、胜负和结算证据，项目入口/库/阶段声明 | 直接改余额、伪造通关/接口结果、重复实现 Recorder/通用提现 |
| 项目任务配置 | `ProjectSettings/IncentiveAutomation.json`：片段、关卡、环境、各国提现数据和录制覆盖 | 框架安装目录或 PackageCache 绝对路径 |
| TestBench（未来） | 设备任务、应用生命周期、手机 Host/采集、日志与运行关联 | 直接复用 UnityEditor/Recorder 实现 |

**后续修改仍遵守同一原则：发现可复用能力先放框架；仅游戏特有的玩法留在游戏。** 当前新游戏通常增加适配器、一个 Editor 程序集、游戏子流程 JSON 和任务配置；现有业务事件不足以观测时，可在正常输入/胜负位置增加双宏保护的只读计数或事件。

### 当前执行链

```text
AI 维护的框架/游戏图 + 项目片段配置
  → 根据游戏声明组合六个阶段、筛选本次国家、排序片段
  → 启动前校验、生成本轮收款资料、冻结运行快照
  → FlowEditorRunner / FlowEngine
  → FlowEditorHost → framework.* / game.* / 共享输入与时钟 / Recorder
  → reports + config + diagnostics + 仅视频的交付目录
```

新玩法替换六个游戏阶段的实现；使用相同框架页面时继续复用通用素材主流程。新增业务模块或完全不同的业务页面时，仍需增加对应图/能力，不能承诺仅改配置即可接入所有游戏。

## 4. 素材流程的当前业务规则

### 4.1 片段与执行顺序

| 片段 ID | 录制起点 | 录制终点 | 主要配置 |
| --- | --- | --- | --- |
| `level_success` | 目标关卡实际开始加载 | 金币动画结束；勾选且达门槛时延长至提现成功页展示完成 | `level`、`on_ahead`、`Withdrawal` |
| `level_failure` | 目标关卡实际开始加载 | 正常失败、失败弹框出现并停留 | `level`、`on_ahead`，计划级停留时间 |

可增加多个成功/失败片段，单个计划最多100个，每个成功片段各自勾选附加提现及配置资料。成功默认5关、失败默认6关，附加提现默认关闭。**Fortuna当前为成功5关不附加、成功6关附加提现、失败7关**；项目覆盖优先。

执行器将显式关卡升序排列，同关先失败后成功，`level=0`随后；附加提现跟随所属成功，不参与关卡排序，不额外计为视频。相同正关卡多个成功仍会被拒绝。

### 4.2 准备、引导与广告

- 当前关卡为1且需要跳到后续关时，先通过正常玩法完成首关及奖励。提现引导按真实余额条件出现，首关不足门槛不会无条件等待。
- 后续跳关逐关请求现有升级接口，核对 `user/info`，有领奖资格才真实领取并刷新权威余额；不展示跳关奖励动画，不用本地修改关卡/余额代替请求。准备不录制。
- 当前关超过目标时，`on_ahead=stop` 直接停止；`delete_account` 在测试接口确认删号成功后清本地并重启。不会在录屏中重启，也不自动重发失败的升级/领奖/删号提交。
- 跳关结束、没有继续提现的成功片段停录后检查引导。勾选附加提现且余额达门槛时，录屏内直接按正常入口（包括实际引导入口）进入提现页，不在中间做往返。
- 本轮取消专门补币流程。金币动画结束后读取余额/门槛，未达到则记录`skipped / insufficient_balance`并结束游戏成功视频；不因此等待或失败。未知余额/门槛及真实提现接口拒绝仍失败。
- 所有自动化广告统一走成功回调；不看 SDK/H5 广告，不伪造展示收益，也不绕过接口资格和业务码。
- 页面停留默认1000ms，失败弹框停留2000ms，输入约200ms/字且带轻微节奏变化；关中进度宝箱默认抑制，正常通关宝箱保留。

### 4.3 环境、国家和收款资料

日常设置 API/eCPM；国家来自游戏框架配置，在管理页默认全选，运行前可筛选，运行期间锁定。语言按游戏国家映射，不再单独手填。eCPM=0 使用正常 SDK 来源；大于0为本次会话覆盖。

默认收款账号/邮箱/税号按启动时 UTC 时间序列生成，同进程同秒递增，不记录已使用值；生成结果固定在本次快照。各国/渠道分别保存自动或固定模式，旧默认自动识别，手工值保留。BR 税号生成校验位，所有字段继续通过业务格式规则；格式正确不等于服务端接受或真实收款身份有效，也不能保证与其他机器、服务端历史数据绝无重复。

自动化使用临时测试身份作用域；API/国家切换、会话准备和清理会调用宿主清档路径，清理 PlayerPrefs、SaveManager 和 KV 等本地数据。**这不是原存档的完整快照还原**。录制应使用专用测试工程/环境；新游戏接入必须核实额外存档和身份缓存的清理方式。正常测试会话清理本地数据与 `on_ahead=delete_account` 的服务端删号是两件事。

## 5. 配置与日常操作

| 内容 | 当前约定 |
| --- | --- |
| 菜单 | `Tools → 自动化编排`，没有独立“游戏接入”面板 |
| 场景管理窗口 | 非模态浮动工具窗口；点击Unity主窗口后仍保持可见，切到其他应用时隐藏，不支持停靠。页面内容不变；旧窗口首次需关闭重开 |

| 声音 | 缺省/恢复默认关闭；Fortuna 当前显式开启，仅采游戏混音 |
| 查看流程 | 只读，运行中蓝色、通过绿色、失败红色、取消黄色 |

| 场景删除 | 仅项目目录内 schema 2 场景，经名称确认移入系统废纸篓；内置/插件/子流程库不能删 |
| 删除保护 | 运行、未保存配置或相关录屏设置打开时阻断；确认期间文件变化拒绝删除 |

保存片段配置校验全部支持国家；管理页启动只组合/预检勾选国家，CLI默认全部。内置场景的设置写宿主项目覆盖；既有独立场景显式保存的20Mbps等值会保留，恢复默认才改为10Mbps。删除场景保留历史录屏、运行快照及共享配置；不会借删除场景顺带清理整个项目。

## 6. 输出与故障定位

```text
AutomationOutput/
└── yyyy-MM-dd_HH-mm-ss/              # 本机本地时间，精确到秒，不加短ID
    ├── video_<游戏工程目录名>/
    │   ├── ID/*.mp4
    │   └── BR/*.mp4                 # 每个国家目录仅放视频
    ├── reports/
    │   ├── report.md
    │   ├── suite-report.json
    │   └── materials.json
    ├── config/                     # 执行快照、运行元数据
    └── diagnostics/
        └── <国家>/                 # 执行步骤、截图、网络信息、失败/中断视频
```

一次运行一个目录；同秒冲突等待下一个可用秒，不覆盖旧目录。成功视频移动交付，单份存储。**当前要求整国片段及清理全部通过才交付该国视频**；后面的提现失败时，已完成游戏片段也可能留在该国 `diagnostics`，不代表丢失。按片段独立交付尚未实施。

排查顺序：`reports/report.md` → `suite-report.json` 中该国结果/错误/清理状态 → `diagnostics/<国家>/report.json` → `network-summary.json` / `network.jsonl`。请求和响应来自 `NetWorkLog:Request/Response`，区分 HTTP 状态与业务码，包含节点上下文并脱敏凭证。没有请求ID时不伪造并发配对。

| 现象 | 优先核对 |
| --- | --- |
| HTTP200 但提现失败 | 业务错误码、消息、账号绑定、余额/渠道资格，不能按 HTTP200 判成功 |
| video 目录为空 | 国家是否在准备阶段失败，或提现失败导致整国未交付；再查 diagnostics |
| 长时间没有新视频 | 当前是否正在跳关；准备阶段本来就不录制 |
| 勾选提现但视频没提现 | 查看附加提现结果是否为`insufficient_balance`；报告包含当时余额/门槛 |
| 首关等不到引导 | 余额/门槛、HasShown、协调器及当前实际引导，不能写完成标记跳过 |
| 前台/后台卡顿 | 分别检查 Editor 失焦限速和监控/玩法开销，不能直接把失败都归因后台 |
| 复制场景仍20Mbps | 是副本的显式设置；默认值变更不会静默覆盖它 |
| 窗口配置改变但结果没变 | 本次使用已冻结快照；旧报告不能套用到新配置 |
