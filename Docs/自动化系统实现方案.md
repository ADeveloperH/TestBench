## 2. 目标与三层边界

AI维护代码和流程，使用者配置任务并启动确定性执行；运行期间不依赖模型临时决策。可视化用于只读查看流程及状态，不要求使用者手工连节点。

| 层 | 维护职责 |
| --- | --- |
| 独立自动化插件 | 能力契约、注册/校验/执行、标准玩法驱动、共享输入、诊断、Editor任务组合/录屏/交付、统一AI助手与通用规范 |
| 激励业务扩展 | framework.*奖励/提现/业务跳关/环境/业务页面、业务模板及AI补充声明 |
| 游戏 | Runtime适配器及显式注册，真实配置/加载/正常输入/接受/效果/胜负/结果交接证据 |
| TestBench | 设备任务、应用生命周期、通信、手机宿主/媒体与日志关联 |

公共插件不引用激励或具体游戏程序集；业务扩展单向依赖插件Runtime，业务Hook只通过宏内观察接入正常业务。游戏不复制执行器、循环、Recorder或奖励/提现逻辑。

## 3. 目录与配置

独立包在IncentiveEngine/Packages/com.foundation.unity.automation，下分Runtime、Editor、Templates、AI和Docs。激励扩展在IncentiveEngine/Assets/Automation，下分Runtime、Editor、Templates和Docs；Editor/Integration仅声明业务补充，完整AI助手位于插件Editor/Onboarding。

| 路径/标识 | 当前约定 |
| --- | --- |
| ProjectSettings/Automation.json | 游戏保存任务、节奏及录屏覆盖；根版本1、计划版本4，激励参数在Extensions.incentive |
| Assets/Automation/Runtime | 游戏自己的Runtime适配器及无Editor平台限制的asmdef |
| Library/AutomationAI | 插件的本机包定位及静态预检报告，排除Git |
| Foundation.Automation.* | 公共程序集及Editor会话/偏好标识 |
| AutomationOutput | 本次运行的配置、报告、诊断和视频，排除Git和包体 |

新命名不兼容读取旧配置或缓存。保留手工任务时须明确按当前格式整理到新配置，不能静默丢失；本轮不修改现有游戏，因此不重复验证游戏录制。框架升级后刷新助手并重新复制提示词。共享游戏源码/meta/任务/依赖及文档，本机定位和录制产物不共享。

本地游戏分别引用激励Assets和自动化包，激励发布包声明自动化确定版本依赖；本地显式file覆盖仅用于联调，不把个人绝对路径写入发布包依赖。本轮不发布。

## 4. 模板与执行链

两端共用Runtime/Compilation；Editor选择唯一业务工作流：没有扩展时用插件默认Templates；安装激励扩展时用激励Templates。两份material_capture.json/material_modules.json是不同方案，不是镜像。Fixtures/control_flow.json仅为模拟Host回归数据。

```text
主模板 + 模块库 + 标准游戏阶段 + 项目配置
  → 筛选分组、排序片段、校验并冻结FlowDocument
  → Editor：FlowEditorRunner → FlowEngine → EditorHost/Recorder
  → Android：构建目录 + TestBench计划 → 共用编译器 → FlowRemoteBootstrap/FlowRuntimeSession → 同一FlowEngine
  → game.*交游戏、framework.*交业务、capture.*交宿主
```

Editor通过TypeCache发现提供者，Player必须显式RegisterGame<T>/RegisterFramework<T>。Player不从Assets/ProjectSettings/包路径寻找模板；专用自动化构建临时启动场景提供模板和默认任务目录，TestBench提交计划，由手机同一编译器生成冻结文档。launch在Player只确认应用已运行，设备启动由TestBench/adb管理。无capture宿主不能执行录制节点。

## 5. 素材与玩法的当前要求

- 成功/失败片段可多次配置关卡，默认成功5、失败6；正关卡升序、同关失败优先、0使用届时当前关。
- 激励成功从真实加载开始，经真实通关、奖励和金币动画完成；可同一视频附加提现。余额不足只跳过提现，保留成功素材并记录原因，真实业务拒绝仍失败。
- 激励失败以真实整关失败和稳定失败画面为终点。多波次允许前波成功后在后波失败，开局无法失败时可正常创造条件；误通关不能当失败素材。
- 游戏只读决策和失败规划，框架统一观察、输入接受、效果确认、拟人停顿及预算。当前无窗口不等永久不可达；规则不可达只结束当前片段并保留诊断，后续继续。
- 准备关卡不录制。激励扩展使用真实接口逐关升级、资格允许时领奖；首关教程和实际出现的提现引导正常处理。
- 素材显式启用广告成功回调，普通功能测试默认不跳广告。页面停留与玩法节奏分开，不把所有在途动作结束当作下一次可输入条件。
- TaskEntryIcon在整次激励自动化执行隐藏，结束恢复；不是只在录制期间隐藏。

业务具体参数和完成条件只在所属业务能力参考维护。不能从提示词或编译推断游戏求解策略正确。

## 6. 输出与故障定位

```text
AutomationOutput/yyyy-MM-dd_HH-mm-ss/
  video_<游戏工程>/<国家或DEFAULT>/*.mp4
  reports/        # report.md、suite-report.json、materials.json
  config/         # 本次冻结配置
  diagnostics/    # 步骤、截图、网络及失败/中断素材
```

本机本地时间精确到秒，无短ID；同秒冲突不覆盖。video目录只放有效完成视频，每个片段独立交付，后续失败/取消不扣留。中断/无效/规则不可达留diagnostics。

Editor排查先看reports/report.md和suite-report.json，再查分组report.json、segments.json及network-summary.json/network.jsonl。TestBench首版先看reports/materials.json和<国家>-error.json，再查<国家>-full.json与diagnostics/<国家>/network.jsonl；其文件职责见手机自动化素材录制.md。保存真实错误码和NetWorkLog:Request/Response，区分HTTP与业务码，凭证脱敏；不得将未关联的最近请求错误当作当前根因。

默认1080×1920、30fps、10Mbps、声音关闭；手工覆盖保留，实际媒体需用户验证。后台输入隔离、失焦帧率和录屏性能仍有边界，不能宣称已经全部解决。

## 7. 正式包与后续工作

执行代码和Runtime程序集以ENABLE_AUTOMATION隔离，自动化Player通过AutomationPlayerBuild.BuildPlayer专用入口构建，Development非必需；普通TEST包不启用自动化宏；激励环境覆盖/准备/提现另需TEST。正式包禁止ENABLE_AUTOMATION，插件构建保护检查宏、预载/场景及专用资源。外部资源流水线也须排除专用资源，未做正式产物扫描不能宣称包体已验收。

后续由用户验证编译、Editor真实成功/失败/附加提现、不同玩法和不同AI接入、Player输入及取消释放、正式构建与资源排除。当前已实现Android桥/采集代码，尚无支持自动化APK；真实启动、玩法、奖励/提现、媒体及断线收尾留待真机验收。本轮两个游戏未修改，不重复实测。

维护时先更新受影响契约，再改代码、能力参考、AI文件清单、资源路径和文档导航。通用规范只维护一份，业务规范只写差异，不再追加互相覆盖的历史规则。

## TestBench自动化界面与本机方案

自动化Tab定位为“自动化测试”，设备/应用在创建时固定，页面以只读身份和连接操作展示；日志/用例入口仅在各自Tab。游戏测试包导出场景与默认参数，TestBench按应用＋场景管理多个具名执行方案，保存于应用数据目录automation/plans/<包名>/<场景ID>/plans.json，可跨设备复用；旧设备缓存幂等迁移，草稿独立保留，默认值不反写测试包。参数管理和运行期间锁定、导入导出、并发修订及验收范围见[手机自动化测试约定](手机自动化素材录制.md)。
