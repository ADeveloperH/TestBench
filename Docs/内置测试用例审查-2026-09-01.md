规则引擎目前已经支持：

- AND / OR 条件树
- `contains / equals / regex` 等匹配
- `minCount` 累计次数
- `absence` 锚点与缺失观察窗口
- 按应用 scope 控制用例可见性

仍存在的能力边界：

- 测试 Tab 会先按目标应用 PID 过滤日志，无法检测 `ActivityManager` 等系统进程日志。

- 缺失判定必须使用真实、稳定、顺序正确的锚点。
- scope 的 `global` 表示适用于所有应用，不表示规则可以读取所有 PID。

### 新增广告 eCPM 监控用例

新增 `ie_ad_ecpm_fail`，归入“广告”分组，包含两条独立的 error 规则：

- `Android.Stats` 的 `UpdateEcpm` 事件中 `price=-1` 或 `price=-1.0`。
- `Unity` 的 `NetWorkLog:Request` 中，`JsonParams` 的 `ecpm=0` 或 `ecpm=0.0`。

任一规则命中即判定用例失败；无异常日志时保持“监控中”，不提前显示“通过”。

### 新增 Adjust 收入回传监控用例

新增 `ie_adjust_revenue_fail`，归入“广告”分组，使用两条带 Tag 约束的 pass 规则：

- `Android.revenueToMMP` + `max to adjust suc`。
- `Android.revenueToMMP` + `topon To Adjust suc`。

两条成功信号都出现才显示“通过”；用例设置 `requirePass=true`，因此只出现一条或尚未出现时显示“疑似”，主动提醒关注，但不代表已经捕获到明确错误。

### 新增 UA 埋点监控用例

新增 `ie_ua_adjust_event`，归入“埋点”分组，要求 tag 精确等于 `Android.AdjustCollector`，且消息包含 `onSpecialEvent()`。

`onSpecialEvent()` 可在 `sdkbasecore` 的 `Stats.java` 中定位到 UA 特殊事件上报入口；运行时 tag 以真机样例为准。用例设置 `requirePass=true`：尚未观察到该日志时显示“疑似”，任意一条符合条件的日志出现后显示“通过”。

## 五、暂不加入的候选

| 候选 | 暂缓原因 |
|---|---|
| Push 全量错误日志 | 当前 `UnityPlugin/pushplugin` 可见代码主要是 Editor Host 生成器，旧规划中的 Unity Runtime exception 文案在当前仓库未找到；Android push 又大量使用 `YLog.e` 打印普通步骤，需先确认实际接入版本和稳定错误文案。 |
| 广告普通加载/展示失败 | 属于可能恢复的运行时结果，不能等同集成失败；后续应做“用户主动测试广告”的专项用例。 |
| Beyla `upload result failed!` | 网络抖动会触发，且当前 `minCount` 没有时间窗口；建议先做日志筛选或等连续失败窗口能力。 |
| SDKConfig 云端拉取失败 | SDK 有本地缓存与重试，单次失败不能直接判业务失败。 |
| `ServerError - Type:` / `InvalidData - Type:` | 框架源码中目前是预留接口，无真实调用点。 |
| `middleground` 其他仓库 | 仅目录存在，尚无当前 Gradle 依赖或运行日志证据，不能当成已接入 SDK。 |
